# T2.1 Extractor spike: crawl rules, page structure and parsing strategy

- **Tasks:** T2.1.1 to T2.1.5.
- **Date:** 2026-09-23.
- **Question:** what the wiki's rendered HTML exposes for each page kind the
  extractor needs, which list pages allow discovery without the disallowed
  category pagination, and how the server behaves towards a polite crawler.
- **Sources:** the pages listed in §2, fetched once each with the spike
  User-Agent and at least 3 s between requests; the 72 skill pages already in
  `.cache/wiki/` from P1 (read, not re-fetched).
- **Approval:** the plan marks T2.1.1, T2.1.2 and T2.1.4 as owner-approved.
  This session ran unattended with the owner's standing permission, so the
  fetches were made (18 requests in total) and the strategy in §5 was fixed
  without a sign-off. The decision is logged in
  [fallout-tasks.md](../plan/fallout-tasks.md) §8 as F2.1.

## 1. Crawl rules and server behaviour (T2.1.1)

### robots.txt

Fetched 2026-09-23. One group, `User-agent: *`, no `Allow` lines and no
`Crawl-delay`:

| Rule | Path |
| --- | --- |
| Disallow | `/index.php` |
| Disallow | `/api.php` |
| Disallow | `/load.php` |
| Disallow | `/wiki/Special:*` |
| Disallow | `/wiki/Spezial:*` |
| Disallow | `/wiki/Spécial:*` |
| Disallow | `/wiki/Especial:*` |

- This matches C1, with two additions C1 did not list: `/load.php` (the
  resource loader, which an HTML-only crawler never requests anyway) and the
  localised spellings of `Special:`.
- **The rules use a `*` wildcard.** The robots parser must therefore support
  wildcard matching, not only plain prefixes; a prefix-only parser would read
  `/wiki/Special:*` as a literal and let `/wiki/Special:Random` through.
- The file carries `Last-Modified: Mon, 02 Feb 2026` and an `ETag`.

### GWW:Bots

The policy is about **editing** bots: accounts in the bot group, a way to
pause them within five edits, and a user page naming the operator. It says
nothing about read-only crawlers, rates or user agents. Nothing in it changes
EXT-1 to EXT-7.

### Response headers on an article

`GET /wiki/Energy_Surge` returned 200 with:

| Header | Value | Meaning for us |
| --- | --- | --- |
| `ETag` | **absent** | `If-None-Match` is useless |
| `Last-Modified` | present | set by the Varnish cache per render, so it differs between cache nodes |
| `Cache-Control` | `s-maxage=18000, must-revalidate, max-age=0` | pages are cached server-side for 5 h |
| redirects | none | |

### Conditional requests (verifies EXT-5's [Proposed] part)

| Request | Result |
| --- | --- |
| `If-None-Match` with the (empty) ETag | 200 — no ETag exists to match |
| `If-Modified-Since` with the `Last-Modified` from the first response | **304 Not Modified** |

**Conclusion:** the server honours `If-Modified-Since`. The extractor sends it
with the stored `Last-Modified` value, verbatim, and never sends
`If-None-Match`. Because `Last-Modified` reflects the render time on a cache
node rather than the edit time, a 200 does not prove the page changed — the
diff (WP2.7) compares extracted values, never fetch results.

## 3. Where each field lives (T2.1.3)

### Skill pages

The infobox is `div.infobox.skill-box.<Profession>`. Profession-less skills
(PvE-only) have `skill-box` with no second class; monster skills have
`skill-box Monster Monster`.

| Field (§9.3) | Where | Example |
| --- | --- | --- |
| **Skill ID** | **`div.skill-image a[title]`** (also the `img` `alt`) | `title="39"` on Energy Surge |
| Name | `p.skill-name b` | |
| Energy, adrenaline, sacrifice, upkeep, overcast, activation, recharge | `div.skill-stats li`: the text before the link is the value; the link's `title` names the field (`Energy`, `Adrenaline`, `Sacrifice`, `Upkeep`, `Overcast`, `Activation`, `Recharge`) | `<li>5 <a title="Energy">` |
| Profession | `dl dt` "Profession" → `dd` | `Mesmer`; `Monster` for monster skills |
| Attribute | `dt` "Attribute" → `dd`; **absent** for no-attribute skills; a title track for PvE-only skills | `Domination Magic`, `Asura rank` |
| Type and elite | `dt` "Type" → `dd`; elite is a leading word | `Elite hex spell`, `Elite  skill` (two spaces) |
| PvE-only | `dd` of Type contains `<small>(PvE-only)</small>` | Air of Superiority |
| Campaign | `dt` "Campaign" or "Campaigns" → `dd`; several are comma-separated | `Core`, `Eye of the North` |
| Special | `dt` "Special" → `dd` | `Resurrection skill`, `Monster skill` |
| Target | category `Skills that target foes / allies / other allies / dead party members`, `Untargeted skills` | |
| Range | category `Casting ranged skills`, `Half ranged skills`, `Point blank skills` | |
| AoE | category `Skills with adjacent / nearby / in the area / earshot / spirit / large spirit / party AoE` | |
| Flags | categories `Projectile spells`, `Easily interrupted skills`, `Armor-ignoring damage`, `Elite skills`, `Sacrifice skills`, `PvE versions of skills` | |
| Scaled values | `table.skill-progression`: row labels are `div.var` in the first `td`; each rank is a `div.column` holding `div.attr` (the rank) and one `div.var` per row | ranks 0–21 (22 columns) or 0–20 (21) |
| Description | first `div.noexcerpt p`; also a concise version in the second `div.noexcerpt` | read only to hash (EXT-7) |
| `x…y…z` text | yes, as `span` with green bold style inside the description | `1...8...10` |
| Categories | the `wgCategories` array in the page's inline script, and the `#catlinks` block | |

- **The ID is displayed on every skill page**, which the design did not
  expect (§9.3 said "the skill ID may not be displayed"). This removes the
  need to join on titles for the ID at all.
- **Target, range and AoE are not in the infobox.** They come from the
  categories the infobox template assigns.
- **Title-track progressions** run over title ranks 0–10, with ranks 0 and 5
  in bold. Asura rank 4 gives effective rank 12 and rank 5 gives 15, which
  matches `titles.ron`.
- **Every progression value in the 74 pages is an integer.** 2,542 cells
  were checked against the Gr formula (§8.3) with round-half-up; the only
  17 mismatches are all in one row, Energy Surge's "Total Damage (Target)",
  which is a derived row (7 × energy lost) rather than a Gr row. Such rows
  are flagged `special_rounding`.
- Row labels sometimes carry a footnote digit (`Energy gain1` on Spirit
  Siphon) or a non-breaking space (`Sacrifice %`). Both are normalised away.

### Split PvE/PvP pages

There is no "PvE version" heading on the page. The PvE skill lives at the
plain title, the PvP version at `<Title> (PvP)`, and the PvE page is in
`Category:PvE versions of skills`. **Decision:** take the plain title; skip
any title ending in `(PvP)` (D3).

### Foe pages (`table.infobox.npc-infobox`)

| Field | Where | Example |
| --- | --- | --- |
| Name | first `th` | |
| Affiliation | `th` "Affiliation" → `td` link | `Kournan military` |
| Species | `th` "Type" → `td` | `Human` |
| Professions | `th` "Profession" → `td` link titles | `Mesmer` |
| Levels | `th` "Level(s)" → `td` text, **a list of `NM (HM)` pairs** separated by commas or `<br>` | `16 (25), 20 (26)` |
| Campaign(s) | `th` "Campaign(s)" | |
| Boss | the infobox class or a `Boss` row (none on the Kournan pages) | |
| Attributes | the first `p` under `h2#Skills` (or under each `h3` variant) | `15 Domination Magic, 14 Inspiration Magic (20 Domination Magic in Hard mode)` |
| Skills | `li` under `h2#Skills`, skill link title, then notes in parentheses | `(elite, level 20 and above only)`; `(Hard mode only)` |
| Variants | an `h3` per variant inside the Skills section | Kournan Guard: axe, hammer, sword |

- **The "a / b" armor pairs in §20.2 are physical vs elemental.** The Guard's
  116 is blunt, piercing and slashing; its 96 is cold, earth, fire and
  lightning. The table states level 20.
- The Guard page has three variants (axe/sword share a skill list; hammer;
  sword in one mission), each with its own skills, and two armor tables.

### Area pages

- `h3#Foes`, then per group a `p` with the group name, then `ul li` rows of
  profession icon (its `title`), level text `NM (HM)`, and the foe link.
- `h4#Bosses` follows the same shape, with the boss's elite skill after `→`.
- Vehtendi Valley lists all eight Kournan foes at `20 (26)` under
  "Humans (Kournan military)".

`li` items: skill link, optional `(BOTH)` or `(PvE)`, then ` - ` and the
change in words. Used as context in the change report only.

## 4. Value formats that need normalising

| Format | Example | Rule |
| --- | --- | --- |
| Fractions | `<span style="display:none">0.75</span><big>¾</big>`, `1½` | use the hidden sort key when present; otherwise map `¼ ½ ¾` and `N¼ N½ N¾` |
| Percent sacrifice | `33%`, `17%` | integer percent |
| Variable sacrifice | `5%+` (Blood of the Master) | the number; record "variable" in the provenance notes |
| Upkeep | `-1` | signed pips |
| Adrenaline | `5` | strikes |
| Overcast | `10` | energy |
| Type with elite | `Elite  skill` | collapse whitespace, strip the leading "Elite" into the flag |
| No attribute | the Attribute row is absent | `None` |
| Title track | `Asura rank` | `title_track: Some(Asura)`, attribute `None` |
| Campaign | `Core`, `Eye of the North` | enum |

## 5. Strategy (T2.1.4)

1. **Skill IDs:** from the skill page itself (the infobox image title).
   `Skill_template_format/Skill_list` supplies the ID and title for discovery
   and the index; the game-integration pages are parsed too, for monster
   skills and as a cross-check. An ID that disagrees between the page and the
   list is reported, never guessed.
2. **Scaled values:** the progression table only. The description's `x…y…z`
   is compared as a check and never stored. Rows whose values do not follow
   the Gr formula keep the page's values and are flagged `special_rounding`.
3. **Split pages:** the plain title is the PvE version; `(PvP)` titles are
   skipped (D3).
4. **Discovery:** `Skill_template_format/Skill_list` (IDs), the 11 profession
   list pages (profession, attribute, campaign, elite), List of PvE-only
   skills (flag), and area pages' Foes sections for creatures. About 20 pages.
5. **Normalisation:** §4.
6. **Conditional requests:** send `If-Modified-Since` with the stored
   `Last-Modified`; treat 304 as "keep the cached copy". Never send
   `If-None-Match`.
7. **Target, range and AoE** come from categories (§3), not the infobox.

DESIGN §9.2 and §9.3 are updated to match.

## 6. Synthetic fixtures (T2.1.5)

`crates/gwsim-extractor/tests/fixtures/` holds one minimal HTML file per page
kind, copying the tags, classes and table layout of the real pages with
invented numbers and placeholder prose. See the README there.

## 7. Open questions

- **Boss pages** were not sampled: none of the M1 foes is a boss. The boss
  flag's source is therefore unconfirmed; the parser looks for a `Boss` row
  and the `boss` link, and reports nothing found as "not a boss".
- **Monster skill IDs** above 3473 are not in the skill list. The
  game-integration pages cover them up to 2026-08-08.
