## 1. rustup on Windows

- **rustup-init does offer to install the prerequisites itself.** It can pull in a linker,
  the libraries and the Windows API import libraries through Visual Studio **Community**.
  We do not use that route: gwsim only needs the Build Tools, which are a smaller and
  licence-simpler install than Community.
- **Default host triple:** `x86_64-pc-windows-msvc`. rustup targets the MSVC ABI by default
  on Windows and picks the triple from the host CPU. The development machine is `AMD64`, so
  `x86_64-pc-windows-msvc` is correct. (The GNU ABI is the alternative; we do not use it.)
- **Default profile:** `default`, which is `minimal` (`rustc`, `rust-std`, `cargo`) plus
  `rust-docs`, **`rustfmt`** and **`clippy`**. So a default install already satisfies §18.5
  and T0.2.4 needs no `rustup component add`.
- **Current stable:** **1.98.1**. 1.99.0 is in beta, due 2026-10-01.

## 2. Which Build Tools edition

`winget` currently offers both:

| Edition | Package ID | Version |
| --- | --- | --- |
| Build Tools 2022 | `Microsoft.VisualStudio.2022.BuildTools` | 17.14.41 |
| **Build Tools 2026** | **`Microsoft.VisualStudio.BuildTools`** | **18.10.1** |

Note that the 2026 package ID has **no year in it**; the year-suffixed IDs are the older
editions.

**Decision: use Build Tools 2026.** The rustup book still describes the 2022 edition, but
2026 has shipped and is what a newcomer installing today would get.

The one risk found: Rust's MSVC detection only learned about the 2026 layout in
`find-msvc-tools` 0.1.5, which first shipped in **Rust 1.93**. Stable is 1.98.1, five
releases past that, so this does not affect us. Recorded as the reason the README pins a
minimum Rust rather than just saying "stable".

**Fallback** if the 2026 tools ever misbehave: the same commands with
`--id Microsoft.VisualStudio.2022.BuildTools`. The component IDs below are identical across
both editions, so only the package ID changes.

## 3. Workload and components

The workload ID is `Microsoft.VisualStudio.Workload.VCTools` ("Desktop development with
C++") in both 2022 and 2026.

**The trap:** the MSVC compiler and linker and the Windows SDK are *Recommended*
components of that workload, not *Required* ones. Installing the bare workload gives a
machine with no `link.exe` — the single most common Rust-on-Windows failure. Either pass
`--includeRecommended`, or name the two components explicitly.

| Component | ID | Dependency type |
| --- | --- | --- |
| MSVC C++ x64/x86 build tools (latest) | `Microsoft.VisualStudio.Component.VC.Tools.x86.x64` | Recommended |
| Windows 11 SDK (10.0.26100) | `Microsoft.VisualStudio.Component.Windows11SDK.26100` | Recommended |

**Decision: name the two components explicitly** rather than use `--includeRecommended`.
`--includeRecommended` would also pull in vcpkg, CMake support, AddressSanitizer and the
test tools, none of which gwsim uses. Explicit components keep the install smaller and make
the README say exactly what it installs.

## 5. Admin rights, sizes and PATH

- **Build Tools: needs elevation.** The Visual Studio installer triggers a UAC prompt.
  `winget` will request it; the shell running `winget` does not itself have to be elevated.
- **rustup: no elevation.** It installs per-user under `%USERPROFILE%`.
- **Sizes:** the C++ build tools are the large item. Treat this as an *estimate* of roughly
  1–2 GB downloaded and 3–5 GB on disk; the Visual Studio installer states the exact figure
  before it proceeds. **T0.2.3 must record the real numbers here.** The development machine
  has 662 GB free, so space is not a constraint.
- **A new terminal is required after rustup**, which appends `%USERPROFILE%\.cargo\bin` to
  the user `PATH`. A sign-out is not needed. No new terminal is needed after the Build
  Tools: `rustc` locates MSVC through the Visual Studio registry entries, not `PATH`, so an
  ordinary PowerShell window works and a "Developer Command Prompt" is not required.
- **What changes on the machine:** `%USERPROFILE%\.cargo`, `%USERPROFILE%\.rustup`, the
  user `PATH`, and `%ProgramFiles(x86)%\Microsoft Visual Studio\` plus the Windows SDK under
  `%ProgramFiles(x86)%\Windows Kits\10`.

## 6. The two install routes

### Route A: winget

```powershell
winget install --id Microsoft.VisualStudio.BuildTools --source winget --override "--quiet --wait --norestart --nocache --add Microsoft.VisualStudio.Workload.VCTools --add Microsoft.VisualStudio.Component.VC.Tools.x86.x64 --add Microsoft.VisualStudio.Component.Windows11SDK.26100"
winget install --id Rustlang.Rustup --source winget
winget install --id Git.Git --source winget
```

`--override` **replaces** winget's own installer arguments, so `--quiet --wait --norestart`
have to be repeated inside it; without `--wait` the command returns before the install has
finished.

### Route B: manual

1. Download the Build Tools installer from
   <https://visualstudio.microsoft.com/downloads/> (under "Tools for Visual Studio"), run
   it, tick **Desktop development with C++**, and confirm that **MSVC ... build tools** and
   a **Windows 11 SDK** are ticked in the right-hand pane before installing.
2. Download and run `rustup-init.exe` from <https://rustup.rs>. Accept the default
   (option 1): stable, `x86_64-pc-windows-msvc`, default profile.
3. Install Git from <https://git-scm.com/download/win>.
